# 持久化前端同步验证

版本：client v0.1.0，2026-11-23；模拟后端v0.3.2，生产前端v1.16.0。

已在开发分支加入独立IndexedDB账户缓存与待同步队列，未修改原页面或上线构建。缓存与队列在同一事务提交，展示数据由已确认账本叠加待同步操作生成。服务器成功确认后再删除队首，操作ID与expectedRevision在发送前持久化，确保响应丢失后可以重试同一操作。

## 自动检查结果

backend npm test一次完整通过21项（原13项加第一轮8项同步），随后新增关键冲突案例后，同步测试文件9项全部通过。既有后端代码没有改动，无需把原13项重测冒称为新增案例后的再次完整运行。

| 场景 | 结果 |
|---|---|
| 本地待同步交易，关闭存储再开 | 缓存与操作、固定版本号均恢复 |
| 两个账号与错误API身份 | 缓存隔离，错误绑定拒绝 |
| 服务器提交后响应丢失 | 关闭重开、刷新后仍重试同一wire，D1仅一笔操作 |
| 多标签页同时追加/flush | 事务保留两次编辑，服务器幂等，后续编辑不丢失 |
| 401登录失效 | 保留队列；恢复认证可提交 |
| 成功提交但确认读取失败 | 保存原操作；后来新增编辑按确认后的下一revision提交 |
| 响应丢失后另一设备修改 | 确认先前提交，剩余编辑暂停，不静默重设版本 |
| 直接遇到另一设备修改 | conflict状态，保留本地编辑和云端核对副本 |
| 本地存储失败 | enqueue拒绝，未提示成功/未向服务器提交 |

默认沙箱禁止监听回环端口，首次检查因EPERM失败；用已授权的本地Miniflare监听权限重跑后通过。该失败是执行环境限制，不作为代码通过证据。
