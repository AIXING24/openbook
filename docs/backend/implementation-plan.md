## 顺序与验收

1. 上传已有原型和报告：可在新 checkout 安装运行，无本机固定源码路径，无内嵌 Git、密钥或真实账本。提交须带版本号。
2. CPU 改造：交易逐条入库并索引；导入按小批次校验和提交；按账户、日期及必要的交易批次增量计算；失败、暂停和并发变更可恢复；所有片段完成后才确认每日点。保持旧格式、清仓记录、历史值、隐私百分比口径和近一年滚动保留。本地正确性检查后，在真实免费 Worker 验证 1000 笔/50 标的、冷启动和重复调用的 CPU；10ms 内应有余量。
3. 访问验收：先核查当前 workers.dev 默认解析问题，再测试可用的官方免费域名或已有自定义域名；保持 TLS 验证。手机 Wi-Fi 和蜂窝网络须实测。购买域名、新增付费方案另需用户明确授权。
4. 前端接入：通过带用户认证的接口读写云账本；保留原网址，首次上传先备份，分批暂存、核验后激活；本地缓存与持久化离线队列支持重试；旧快照保持原采集口径，新收盘记录与今日临时值分开。
5. 正式发布：前后端与旧备份兼容验证、模拟迁移和定时落库通过，确认行情日期、历史汇率与股票企业行动口径后，再启用真实账本迁移。不能把固定模拟行情或测试密钥直接用于真实账户。
