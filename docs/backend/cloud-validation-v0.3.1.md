# 后端分批实现与云端验证

版本：backend v0.3.1，2026-11-23。前端仍为 v1.16.0。

本轮已将原型归档到原仓库开发分支，增加规范化交易存储、可恢复的分批导入校验、幂等并发操作和每日增量计算。13项后端检查、34项前端检查通过，前端构建及源码未变化。模拟账户是唯一云端数据，未读取或上传个人账本。

## 实现与证据

- 每笔交易独立入库，保留原ID、排序、币种、清仓记录及已实现盈亏。源备份在客户端经过旧格式完整校验；服务端验证分段内容哈希链。上传暂存与语义校验分属独立请求，必须全部通过且客户端下载对比后才能激活。云端已有账本则拒绝静默覆盖。
- 日计算每次处理10笔交易或5个标的估值，检查点和结果原子保存。缺失/未确认行情或历史汇率不写假点，恢复后续算。下一日期复用有效持仓状态，历史修订才使受影响日期失效并重算归档；近365自然日加前一有效基准的保留不删除交易。
- v0.3.0真实云端验证440次模拟请求：分批上传/校验、1000笔/50标的重算、幂等重试与冻结历史均通过。v0.3.1的5标的估值版本24次请求通过，两个账户的完整金额/百分比口径与原算法一致。报告位于 backend/cloud-recheck-v0.3.0.json、cloud-valuation-v0.3.1.json。
- 真实Cron曾独立完成两个账户的模拟2026-11-24日终点，日期为人为指定的未来模拟日期，不是市场真实收盘记录。最后观测的scheduledTime属于此前版本，因此不作为v0.3.1专属Cron或CPU证明。临时Cron已清空，官方schedules=[]，见backend/cloud-cleanup-v0.3.1.json。

## CPU与免费额度

官方GraphQL CPU字段为微秒，以下已除以1000转成ms。网络耗时、SQL耗时和部署startup time不作为调用CPU。

| 实现/样本 | CPU峰值 | 结论 |
|---|---:|---|
| 原型完整导入 | 78.524ms | 超出Free单次10ms |
| v0.2.0逐条语句/日计算 | 22.007ms | 仍超限 |
| v0.2.1合并SQL的导入 | 10.888ms | 首次批次仍超限 |
| v0.2.2仅缩小交易批次 | 22.387ms | 仅减批次不足以解决 |
| v0.3.0拆开上传与逐片校验：导入阶段 | 5.649ms | 当前模拟导入已留出余量 |
| v0.3.0首次10标的估值所在阶段 | 11.872ms | 仍需进一步拆分 |
| v0.3.1改为5标的：24次对应调用 | 8.788ms | 本次样本全部低于10ms |

v0.3.1官方统计包含24次调用、0个runtime error；独立scheduled CPU数据仍为空。当前模拟规模的请求数与数据库约6.7MB远低于已核实的Free日请求/读写与单库500MB限额。样本通过不代表所有冷启动和大账本均稳定：仍需整年历史的分页/同步验证、更多首次调用样本、真实行情日期与企业行动，以及生产认证。特别是不能在生产每次全量返回整年的大历史JSON。

原始CPU证据见 backend/cloud-metrics-v0.3.0.json、cloud-metrics-v0.3.1.json；前几版统计也保留，避免用最终小批次结果掩盖曾经的超限。
