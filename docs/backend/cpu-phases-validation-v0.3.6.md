归档授权：用户随后明确同意上传结果记录；本批脱敏证据及复现代码归档到既有`dev/gaintrace-backend`，不合并main、不发布线上App。下文未提交/未推送描述保留测试完成时的状态。

## 1. 范围与可证伪假设

用户于2026-11-26明确允许临时Worker及少量合成请求。本轮仅定位已有16.749ms峰值，不修改原计算算法，不读取或上传真实行情密钥，不绑定D1或开启Cron，不迁移个人账本，不扩权限或启用收费服务。此批诊断代码和脱敏结果只在本机，尚未获得本批公开推送授权。

反馈命令：在`backend/`执行`NODE_EXTRA_CA_CERTS=/etc/ssl/cert.pem node scripts/repeat-market-cpu.mjs`运行固定18请求，再执行`NODE_EXTRA_CA_CERTS=/etc/ssl/cert.pem node scripts/capture-market-cpu.mjs`读取官方CPU。前者验证HTTP和合成语义，后者用原有10ms参考线返回`peak-reproduced`、`no-peak-observed`或`inconclusive`，缺样不能通过。既有测试仍用真实云测16.749ms报告验证判定器可变红；不是依靠Node耗时模拟云CPU。

实验区分以下假设，测试前不将任何一项当根因：共享初始化/首次使用；ECB固定CSV解析和5/50标的样本构造；四个独立市场收盘键的IANA转换；证据校验与按标的数组查找。50标的原算法按市场/日期/收盘时间去重，实际只有四次收盘转换，不能用50次转换冒充它。

## 2. 实验结构与口径

- 临时Worker仍为`gaintrace-market-validation`，固定新报告前缀`market-cpu-phases-01`；旧重复与真实云测报告不覆盖。
- 入口`market-phase-validation.mjs`在模块作用域预构造5/50两份固定样本。`control`只做鉴权与短响应；`fixture-5/50`额外新构造样本；`close-four`调用原IANA函数并核对四个预期UTC收盘时间；`gate-5/50`对预构造样本调用原门禁；`evidence-5/50`直接委托原候选HTTP处理器。
- 首轮顺序为control、fixture-5、fixture-50、close-four、gate-5、gate-50、evidence-5、evidence-50，第二轮反向，共16次成功计算；之后验证401未授权和404源路由保护，总18次、间隔3秒、不自动压力重试。
- `summary/history/fx/today-readiness`在新入口全部阻断，即使意外存在源密钥也不能调用源。部署仍为mock-only，真实源密钥不会读入或上传。
- 原`market-validation.mjs` SHA256保持`434a9edb023cbf9951a69655a3a4160ff2cb3b88a923af7873ee70974f7b57af`；原IANA/门禁和FX计算文件不改。

**限制**：模块预构造改变共同初始化成本，拆分阶段多一次用于鉴权的状态响应；完整路径委托原处理器，不多做一次鉴权。故不能简单相减得到某模块的纯CPU或固定提速百分比。官方CPU仍是整个请求的观测，不是`performance.now`、网络等待或部署startup。首个阶段使用不是已证实冷启动，也不证明请求复用同一isolate。每阶段只有两次，不能推断全容量、长期尾部或全部冷启动。控制台CPU是显示整数，舍入未知；精度由独立GraphQL桶提供，时间关联不是request-ID遥测。

## 4. 云端结果

临时Worker于06:57:53.694UTC部署，实际请求06:59:30.485—07:00:26.831UTC。18次客户端均按预期：16次HTTP200，之后401/404保护。官方GraphQL窗口06:59—07:01UTC取得18个唯一单请求桶、0运行时错误、0上游子请求；最大10.754ms，判定`peak-reproduced`，而非免费CPU验收通过。

**结论**：本轮证据把排查重点收窄到门禁调用及其共同运行时/鉴权/响应开销；单独样本构造和四键IANA路径在这两次请求内未观察到峰值，但不能据此排除其在别的环境下的影响。预构造5标的门禁也出现峰值，不支持“只要分离样本构造就解决”或“50标的规模是唯一原因”。峰值出现在第二次阶段调用，不支持用“只发生于首个请求”解释全部现象；不同请求是否同isolate仍未知，不能宣布排除冷启动。门禁数组查找、URL与日期校验、JIT/GC等具体原因没有被本次整请求测量区分，均不可直接认定。

原真实云测最大16.749ms、两次重复9.822/9.606ms和第二轮一个精确桶缺失继续保留；本轮不能覆盖旧峰值或直接宣布免费预算已通过。下一步先做本机保持语义的门禁内部对照，分别验证查找索引和重复URL/日期校验等可测量假设；需要新一批云端对照时再说明请求范围。不得删减来源/日历/企业行动/FX安全校验以换取低数值，也不以本机耗时宣称Cloudflare CPU改善。
