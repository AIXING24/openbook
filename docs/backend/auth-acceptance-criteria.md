# 免付款信息邮箱认证验收条件

2026-11-23。用户希望通用邮箱或手机验证码，并明确暂不提供付款信息；前端保留原GitHub Pages地址，无自有域名，Cloudflare Pages/D1已有免费模拟部署。

## 选型必须满足

- 首版启用及正常免费额度内运行不要求银行卡、PayPal或其他付款信息；不把需付款方式的Free方案视为符合条件。
- 正式环境可以向一般用户邮箱发送数字验证码，无需购买域名。不把开发实例、测试收件人白名单或仅内部账号默认SMTP当成生产能力。
- 明确列出认证用户额度、邮件发送额度、限速与账号审核要求；这些是不同限制。到达免费额度后可拒绝/等待，不自动开通付费。
- 邮箱验证后的身份必须能由后端核实，不能仅相信浏览器提交的email/userId。第三方稳定用户ID按提供方和租户绑定到自己的账本owner。
- 新服务的登录域名、公开取钥域名和后端出网必须在实际网络验证。已有pages.dev可达不能证明新服务也可达。

## 接入验证

1. 用户在官方站点完成免费账号注册及条款；若要求付款信息即停止当前候选。代码/文档先准备，再在所需授权步骤请用户操作。
2. 首次只用模拟账本及用户明确指定的测试邮箱走完整发码/登录/后端确认；验证码、API密钥与令牌不在聊天/公开仓库中传递。
3. 验证错误码、过期码、重复兑换、重发旧码失效、限速、错误用户和伪造身份。托管认证委托提供方处理OTP时，仍需验证服务端身份token与协议防护。
4. 验证手机蜂窝和Wi-Fi上的完整登录，不能只打开一个静态连接页就声称通过。
5. 验证跨域认证和实际读写均由后端确定owner；CORS不是身份验证。所有生产/预览别名一致鉴权。
6. 重新登录、账号切换、退出和会话到期不删除待同步操作；冲突保留可核对的本地编辑，不静默覆盖云端账本。
7. Cloudflare Free上单独测认证与日终操作CPU，保留已完成分批计算的性能证据；新增认证成本不能沿用旧模拟密钥版本的CPU结论。

通过这些条件后，再接分页历史、迁移状态及原页面入口。当前无真实邮箱发码、生产认证或个人账本迁移。
